# Liujin-Chen.github.io

Personal academic website of **Liujin Chen**, Ph.D. candidate in Music Education at the University of South Florida, published with GitHub Pages at <https://liujin-chen.github.io/>.

Plain static HTML, CSS and JavaScript: no framework, no build step at runtime, no analytics, nothing autoplaying. The homepage, projects index, 404 and credits pages use a cream-paper look with hand-drawn accents and a playable piano; the NAfME 2026 poster page and its interactive companion keep the USF-green chalkboard style of the poster session.

## Preview locally

```sh
cd Liujin-Chen.github.io
python3 -m http.server 8080 --bind 127.0.0.1
# open http://127.0.0.1:8080/
```

Double-clicking `index.html` also works (Chrome 136 loads the self-hosted fonts from `file://`); a local server is only needed for the cross-page view transitions, which are silently absent on `file://`, and if your browser blocks web fonts on local files (the pages then fall back to Georgia and a system handwriting font). Everything else works offline – that is by design, and `bash _qa/shots.sh file` takes one `file://` screenshot to prove it.

## Add a project key (`projects/index.html`)

The projects index is a keyboard drawn on its side: every **white key** is a project card, the **black keys** are playable buttons only, and empty white keys are shown as **rests** so the keyboard is never ragged.

1. Copy the whole `<li class="key-card">` block of the existing NAfME key (thumbnail, eyebrow, title, subtitle, meta line, tags, secondary links, note letter) and paste it in place of the first rest key. Edit the text; keep the `more soon` wording on the rest that follows.
2. The main link is `<a class="pkey" href="<slug>/index.html" data-midi="…">`. Give each white key its note from the bottom up and set the note letter to match:

   | key | C4 | D4 | E4 | F4 | G4 | A4 | B4 | C5 |
   |---|---|---|---|---|---|---|---|---|
   | `data-midi` | 60 | 62 | 64 | 65 | 67 | 69 | 71 | 72 |

3. Black keys (`<div class="bkey-wrap"><button type="button" class="bkey" data-midi="…">`) sit between two white keys exactly where a real keyboard has one: **C♯ (61) after C, D♯ (63) after D, none after E, F♯ (66) after F, G♯ (68) after G, A♯ (70) after A, none after B.** Keep that order when you insert or remove keys.
4. Thumbnail: a 3:4 image about 360 px wide (`<slug>/img/<name>-360.jpg`, under 50 KB) inside the card's `div.thumb`; give it a real `alt`.
5. Keep at least three white keys in total (project keys + rests). Then run the checks below and look at the screenshots at phone width – black keys must never cover a title or thumbnail.

## Update the poster or the interactive page

**Poster.** Replace `projects/nafme2026/Nafme_Poster_Liujin2026.pdf` (keep the filename, or change the two PDF links and the `download=` name in `projects/nafme2026/index.html` and the PDF link in `projects/index.html`). Re-render the images (needs poppler-utils and Pillow):

```sh
pdftoppm -png -r 100 -singlefile -aa yes -aaVector yes projects/nafme2026/Nafme_Poster_Liujin2026.pdf _source/poster-3600
python3 - <<'EOF'
from PIL import Image
im = Image.open('_source/poster-3600.png').convert('RGB')
for w in (360, 900, 1800):
    r = im.resize((w, round(im.height * w / im.width)), Image.LANCZOS)
    r.save(f'projects/nafme2026/img/poster-{w}.jpg', quality=82, progressive=True, optimize=True)
    r.save(f'projects/nafme2026/img/poster-{w}.webp', quality=80, method=6)
im.save('projects/nafme2026/img/poster-3600.webp', quality=80, method=6)
EOF
```

Update the "PDF · 3.4 MB" size text where it appears, and the "At a glance" numbers if the poster content changed (the page condenses the poster; it must not claim anything the poster does not).

**Interactive page.** `projects/nafme2026/explore.html` is a copy of `Challenges_…/page/supplement_page.html` with site edits confined to the `<head>`, a `<style id="site">` block, the `nav.sitenav`, the footer links and JavaScript placed after the original modal code. The data – the 16 `.modal` blocks and the word labels – is byte-identical to the source. If `build_page.py` is re-run, regenerate `explore.html` with `python3 _source/build_explore.py` (it re-applies every site edit to the new `supplement_page.html` and asserts each one), then run `python3 _qa/check_explore_data.py` and the other checks. `?kiosk=1` restores the poster-session iPad mode (90-second idle reset, no site navigation).

## Publish or update through the GitHub web UI

0. **Confirm the GitHub username is exactly `Liujin-Chen`.** A repository named `Liujin-Chen.github.io` is served at the root of `https://liujin-chen.github.io/` only for that account. Under any other username it deploys as a *project site* at `https://<username>.github.io/Liujin-Chen.github.io/`, and the absolute URLs in `<link rel="canonical">`, the `og:*` / `twitter:*` tags, `sitemap.xml` and `robots.txt` must be changed to that prefix (every other link is relative and survives either way).
1. Create the repository `Liujin-Chen.github.io`: **Public**, tick "Add a README file" so the default branch `main` exists.
2. **Settings → Pages → Build and deployment**: Source "Deploy from a branch", branch `main`, folder `/ (root)`, Save.
3. **Add file → Create new file**, name `.nojekyll`, content one line (`Jekyll disabled: plain static site.`), commit. This turns off Jekyll so the underscore-free tree is served exactly as uploaded.
4. **Add file → Upload files**: drag the folder `assets/` and commit; then drag `projects/` together with the root files `index.html`, `404.html`, `credits.html`, `README.md` (replaces the generated one), `robots.txt`, `sitemap.xml` and commit again. Dragging folders keeps the paths. Limits: **100 files per drop** and 25 MiB per file – the site is 72 files, so one drop works and two drops stay comfortably under the limit; the largest file, the PDF, is 3.4 MB. Commit directly to `main`.
5. Do **not** upload `bio/`, `Portfolio/`, `Challenges_and_Support_Stragies_in_Online_Piano_Learning/`, `_source/`, `_qa/` or `.claude/`.
6. Wait for the "pages build and deployment" workflow in the Actions tab (one to two minutes), then open <https://liujin-chen.github.io/>. The CDN caches files for about 10 minutes – hard-refresh (Ctrl/Cmd+Shift+R) after an update, and check that <https://liujin-chen.github.io/nope> shows the 404 page.
7. Later edits: "Upload files" with the same paths overwrites; single files can also be edited with the pencil icon. Paths are case-sensitive on Pages – keep everything lowercase except the PDF's original filename.

**Cache busting.** Stylesheets and scripts are linked with `?v=20261002`. After changing any CSS or JS, bump the value in every page so visitors do not get a stale cached file:

```sh
grep -rl 'v=20261002' --include='*.html' . | xargs sed -i 's/v=20261002/v=20261115/g'
```

Also update `<lastmod>` in `sitemap.xml` when a page's content changes.

## Checks before uploading

```sh
python3 _qa/check_links.py      # every relative URL resolves (exact case), no root-absolute or local-path leaks
python3 _qa/check_html.py       # tag balance, duplicate ids, alt/type/href, meta, headings, aria targets
bash _qa/shots.sh               # screenshots of every page at 1440/1024/390 + intro, reduced-motion, modal,
                                # tall-page, retina and file:// runs into _qa/shots/, plus DOM and console checks
```

Both Python scripts exit non-zero when they find a problem; `shots.sh` needs Google Chrome and Pillow. Look at every PNG: headless Chrome cannot test sound, pinch zoom or the `<dialog>` on a real device, so also try the piano, the lightbox and `explore.html` on an iPad/iPhone and an Android phone before announcing the site.
